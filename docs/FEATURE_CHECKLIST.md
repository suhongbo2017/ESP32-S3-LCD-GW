# ESP32-S3 Gateway 功能清单

> 目标：将当前 ESP32-S3 网关逐步扩展为 3D 打印机房/打印机箱的边缘控制节点。
>
> 定位：ESP32-S3 负责实时采集、本地控制、断网自治和 MQTT 接入；Home Assistant 负责自动化、历史数据库、移动端界面、通知和设备整合；摄像头视频优先由独立摄像头设备负责。

## 状态说明

- `已实现`：当前固件已经具备，且已有源码或实机证据。
- `可直接实现`：当前 ESP32-S3 性能和板卡资源适合，主要需要增加组件、驱动和验证。
- `需要外部模块`：ESP32 可以作为控制核心，但需要传感器、驱动、电能计量模块或安全隔离模块。
- `建议独立设备`：功能可以组成系统，但不建议放入当前网关固件。
- `不建议`：当前硬件或安全条件不适合。

## 一、基础系统

| 编号 | 功能 | 状态 | 优先级 | 说明与验收标准 |
|---|---|---|---|---|
| SYS-01 | ESP32-S3 启动与自检 | 已实现 | P0 | 启动日志报告芯片、Flash、PSRAM、分区和关键外设状态；无 panic、abort 或 watchdog。 |
| SYS-02 | 8MB PSRAM 管理 | 已实现 | P0 | PSRAM 初始化和 memory test 通过；大缓冲优先放 PSRAM，内部 RAM 保留给 DMA、网络和实时任务。 |
| SYS-03 | 16MB Flash 与双 OTA 分区 | 已实现 | P0 | `ota_0`/`ota_1` 各 3MB；固件大小不得超过最小 app 分区；OTA 后可正常启动。 |
| SYS-04 | NVS 运行时配置 | 已实现 | P0 | WiFi、MQTT、主题等配置可以通过 Web 保存；NVS 优先于 Kconfig；密码不出现在日志中。 |
| SYS-05 | 看门狗与异常重启记录 | 可直接实现 | P0 | 记录重启原因、异常次数和最近一次异常摘要；异常后仍能恢复网络和控制功能。 |
| SYS-06 | 运行时健康状态 | 已实现/需增强 | P0 | 可查询 uptime、heap、最大连续块、PSRAM、任务状态、MQTT、TF、传感器和链路状态。 |
| SYS-07 | 固件版本与构建标识 | 需增强 | P1 | 串口和 `/api/status` 显示 Git commit、构建时间、固件 SHA256 或版本标签。 |
| SYS-08 | 配置恢复默认值 | 已实现 | P1 | 提供受保护的配置重置接口；重置后设备可通过默认配置启动。 |

## 二、网络与 Home Assistant 接入

| 编号 | 功能 | 状态 | 优先级 | 说明与验收标准 |
|---|---|---|---|---|
| NET-01 | W5500 以太网 | 已实现 | P0 | DHCP 获取地址；网线连接后链路可用；异常断开不会导致设备重启。 |
| NET-02 | WiFi Station | 已实现 | P0 | 使用 NVS 配置连接 WiFi；断线自动重连；连接失败不会阻塞本地控制。 |

| NET-05 | 活跃链路探活 | 可直接实现 | P1 | 在链路已连接但无实际通信时进行 DNS、ARP 或 MQTT 探测。 |
| NET-06 | MQTT 基础连接 | 已实现 | P0 | 支持本地 HA broker；断线自动重连；连接状态可查询。 |
| NET-07 | MQTT Discovery | 已实现/需扩展 | P0 | 传感器、开关、风扇、功率等实体自动出现在 HA。 |
| NET-08 | MQTT 状态与可用性 | 已实现/需扩展 | P0 | 每个实体有 state topic、availability topic 和 offline 状态。 |
| NET-09 | MQTT 命令下发 | 已实现基础能力 | P0 | HA 可以控制灯、风扇和其他安全的低压输出；命令失败有错误反馈。 |
| NET-10 | 断网本地自治 | 可直接实现 | P0 | MQTT 断开时温控、风扇保护、过温告警等本地规则仍然运行。 |
| NET-11 | 断网数据缓存与补传 | 可直接实现 | P1 | 网络恢复后补传关键事件；缓存有容量上限，满时按策略丢弃旧数据。 |
| NET-12 | MQTT TLS | 可直接实现 | P1 | 需要跨网段或公网接入时启用 TLS、证书校验和认证信息。 |
| NET-13 | mDNS | 已实现 | P1 | 可通过 `esp32gw.local` 访问 Web 控制台。 |

| SAFE-08 | OTA 固件完整性 | 已实现基础能力 | P0 | 校验镜像大小、分区容量和启动结果；需要考虑签名验证。 |
| SAFE-09 | 断网自治 | 可直接实现 | P0 | 网络或 HA 不可用时，本地过温保护和手动控制仍然可用。 |
| SAFE-10 | 运行长稳测试 | 进行中 | P0 | 固定链路至少 15 分钟，重要版本继续做 2–24 小时观察。 |
| SAFE-11 | 任务栈和 heap 监测 | 已实现基础能力 | P0 | 记录最低水位和最大连续块；低于阈值时告警而不是继续分配大块内存。 |
| SAFE-12 | 断电恢复 | 需要验证 | P1 | 设备重启后配置、历史记录、输出安全态和 HA 可用性正确恢复。 |

## 十二、推荐实施批次

### P0：可靠控制节点

首批只做可以直接提升实际使用价值和安全性的功能：

1. 两路温湿度：进料箱、打印机箱。
2. 一个箱内灯开关。
3. 一个或两个风扇 PWM 控制。
4. 风扇 TACH 测速和堵转告警。
5. 温度过高时自动提高风扇速度。
6. MQTT Discovery：温度、湿度、灯、风扇、RPM、告警。
7. 设备上电安全态和断网自治。
8. Web Token 强制配置与健康诊断。
9. 固定 ETH/WiFi 链路和 2–24 小时长稳验证。

### P1：设备与能耗完善

1. `device_registry` 统一设备抽象。
2. INA219/INA226 低压电压、电流和功率。
3. 门磁和门状态。
4. 灯光 PWM 调光。
5. 风扇自动/手动模式。
6. 露点和冷凝风险判断。
7. 打印机 API 状态接入。
8. 断网事件缓存和 MQTT 补传。

### P2：摄像头和高级功能

1. 优先接入独立 IP 摄像头。
2. 如确实需要，再用单独 ESP32-CAM 做低帧率图像节点。
3. 当前 ESP32-S3 只考虑低分辨率周期截图或单路 MJPEG。
4. 不把录像、RTSP、H.264/H.265、AI 检测放入当前主网关。

## 十三、当前板卡资源约束

当前板卡已经占用：

- W5500：GPIO10–15
- ST7735S：GPIO16–18、GPIO21
- USB：GPIO19–20
- Flash/PSRAM：GPIO26–32
- TF 卡：GPIO33–38
- UART0/CH340K：GPIO43–44

当前主要可用引脚：

```text
GPIO1–9、GPIO39–42、GPIO47–48
```

设计新增硬件时必须满足：

1. 不占用 W5500、LCD、TF、USB、Flash/PSRAM、UART0 引脚。
2. 不让 GPIO 直接驱动风扇、灯带、继电器或其他功率负载。
3. 市电必须使用认证隔离模块或成品智能插座。
4. 摄像头若需要大量 DVP 引脚，优先改为独立设备。
5. 所有输出必须定义上电默认态、断网行为和故障保护态。
